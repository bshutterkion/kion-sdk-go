# kion-sdk-go

> **This is the `go/` lane of the [kion-sdk monorepo](../README.md).** Spec
> generation (portal → swagger → `fixspec`) is orchestrated from the repo
> **root** — `make refresh-spec VERSION=<v>`, `make gen LANG=go VERSION=<v>` —
> and `fixspec` lives in `../preprocess/`. This directory holds the Go SDK
> itself plus its build/test/generate targets (`make -C go help`). Some path
> references below describe the previous standalone-repo layout.

Typed Go SDK for the [Kion](https://kion.io) cloud governance API, generated from the Kion OpenAPI specification using [ogen](https://ogen.dev).

The SDK ships a separate generated sub-package for each actively supported Kion release. Consumers pick the version that matches their Kion instance, import the corresponding sub-package, and get a strongly-typed client for that version's API.

## Layout

```
kion-sdk-go/
├── kion.go                          # shared, version-agnostic: Config, Option, With*, helpers
├── kion_test.go                     # unit tests for shared helpers
├── errors.go                        # IsNotFound, IsAuthError, IsConflict, StatusCode
├── options.go                       # Config struct
│
├── cmd/
│   ├── fixspec/                     # swagger 2.0 → openapi 3.0 + ogen-specific fixups
│   └── smoketest/                   # manual live-instance smoke test (build tag: smoketest)
│
├── spec/                            # raw swagger and openapi specs per version (gitignored)
│   ├── master/swagger.json          # from portal/master — internal, never released
│   ├── v3_12/swagger.json           # from portal/support-3.12.x
│   ├── v3_13/swagger.json           # from portal/support-3.13.x
│   ├── v3_14/swagger.json           # from portal/support-3.14.x
│   ├── v3_15/swagger.json           # from portal/support-3.15.x
│   └── v3_16/swagger.json           # from portal/support-3.16.x
│
├── generated/                       # one ogen sub-package per version
│   ├── master/                      # package master (internal/dev only, NOT a customer target)
│   │   ├── oas_*.go                 # generated by ogen
│   │   ├── client.go                # hand-written: New(baseURL, opts...)
│   │   └── auth.go                  # hand-written: bearerAuth (SecuritySource impl)
│   ├── v3_12/                       # package v3_12
│   ├── v3_13/                       # package v3_13
│   ├── v3_14/                       # package v3_14
│   ├── v3_15/                       # package v3_15
│   └── v3_16/                       # package v3_16
│
├── integration_test.go              # live-instance tests (build tag: integration)
├── Makefile                         # all workflows — see `make help`
└── bin/                             # gitignored: project-local swagger + fixspec binaries
```

`master` is a development target inside the SDK — it tracks `portal/master` so we can validate unreleased Kion APIs and prepare the next support-branch snapshot. Master never ships to customers. Only `v3_12` through `v3_16` correspond to Kion versions customers actually run.

## Versioning model

Kion releases multiple minor versions per year, and each is supported for 4 major releases (3 behind the newest). As of this writing:

| SDK sub-package | Portal branch         | Customer-facing Kion version |
|-----------------|-----------------------|------------------------------|
| `generated/v3_16` | `portal/support-3.16.x` | Kion 3.16.x (current) |
| `generated/v3_15` | `portal/support-3.15.x` | Kion 3.15.x (1 behind) |
| `generated/v3_14` | `portal/support-3.14.x` | Kion 3.14.x (2 behind) |
| `generated/v3_13` | `portal/support-3.13.x` | Kion 3.13.x (3 behind) |
| `generated/v3_12` | `portal/support-3.12.x` | Kion 3.12.x (4 behind, carried past the standard window) |
| `generated/master` | `portal/master`         | unreleased dev |

`v3_12` sits one release beyond the standard current-plus-3 window; it's kept for now and can be dropped once Kion officially ends 3.12 support. When Kion cuts the next support branch (`support-3.17.x`), add a `v3_17` sub-package and drop the oldest as the window rolls forward.

## Installation

This SDK is an internal tool hosted on GitLab (`git.kion.io`) and is **not** published to a public proxy. Tell the Go toolchain to fetch it directly instead of through `proxy.golang.org`:

```bash
export GOPRIVATE=git.kion.io/*
go get github.com/kionsoftware/kion-sdk-go
```

`go get` authenticates to GitLab over your existing git credentials. If it can't reach the repo, add an `insteadOf` rule so Go fetches over SSH/authenticated HTTPS:

```bash
git config --global url."git@git.kion.io:".insteadOf "https://git.kion.io/"
```

Then import both the root `kion` package (for shared options and error helpers) AND the specific version's sub-package:

```go
import (
    kion "github.com/kionsoftware/kion-sdk-go"
    v3_15 "github.com/kionsoftware/kion-sdk-go/generated/v3_15"
)
```

## Quick start

```go
package main

import (
    "context"
    "fmt"
    "log"

    kion "github.com/kionsoftware/kion-sdk-go"
    v3_15 "github.com/kionsoftware/kion-sdk-go/generated/v3_15"
)

func main() {
    client, err := v3_15.New("https://kion.example.com",
        kion.WithAPIKey("your-api-key"),
    )
    if err != nil {
        log.Fatal(err)
    }

    ctx := context.Background()

    res, err := client.GetLabelIndex(ctx, v3_15.GetLabelIndexParams{})
    if err != nil {
        log.Fatal(err)
    }

    switch v := res.(type) {
    case *v3_15.LabelListPaginatedResponse:
        for _, label := range v.Data.Value.Items.Value {
            fmt.Printf("%s:%s (color: #%s)\n", label.Key, label.Value, label.Color)
        }
    case *v3_15.UnauthorizedResponse:
        log.Fatal("unauthorized — check your API key")
    }
}
```

### Talking to multiple Kion versions from one program

Because each version is its own Go package, a single program can import and use several versions at once:

```go
import (
    kion "github.com/kionsoftware/kion-sdk-go"
    v3_14 "github.com/kionsoftware/kion-sdk-go/generated/v3_14"
    v3_15 "github.com/kionsoftware/kion-sdk-go/generated/v3_15"
)

// Talk to a Kion 3.14 instance and a Kion 3.15 instance in the same process.
prod, _ := v3_15.New("https://prod.kion.example.com", kion.WithAPIKey(prodKey))
lab,  _ := v3_14.New("https://lab.kion.example.com",  kion.WithAPIKey(labKey))
```

## Authentication

Both auth methods use the `Authorization: Bearer <value>` header. Options come from the root `kion` package and apply to any version's `New`:

```go
// API key auth (most common)
client, _ := v3_15.New(url, kion.WithAPIKey("app_128_..."))

// Bearer (auth) token — takes precedence if both are set
client, _ := v3_15.New(url, kion.WithBearerToken("eyJ..."))
```

## Client options

```go
client, err := v3_15.New("https://kion.example.com",
    kion.WithAPIKey("your-key"),
    kion.WithSkipVerify(true),              // disable TLS verification
    kion.WithTimeout(60 * time.Second),     // custom timeout (default: 30s)
    kion.WithHTTPClient(customHTTPClient),  // fully custom http.Client
)
```

## Error handling

Error helpers live in the root `kion` package and work against errors returned by any version's client:

```go
res, err := client.GetProject(ctx, v3_15.GetProjectParams{ID: 42})
if err != nil {
    switch {
    case kion.IsNotFound(err):
        // 404
    case kion.IsAuthError(err):
        // 401 or 403
    case kion.IsConflict(err):
        // 409
    }
    code := kion.StatusCode(err) // raw HTTP status, 0 if not a status error
}
```

## Development

### Prerequisites

- **Go 1.25.x** for building the SDK itself (`go.mod` requires 1.25.5; portal pins **1.25.11** and this repo's CI runs on `golang:1.25`). Avoid Go 1.26.x locally — the pinned `golangci-lint` can't parse a newer-than-itself stdlib and will panic. Match portal's 1.25.11 (`brew install go@1.25`).
- **git**, **curl** for pulling portal and go-swagger sources
- **[ogen](https://ogen.dev) CLI** and **go-swagger v0.30.5** — both installed automatically by `make deps`
- **A local checkout of [portal](https://git.kion.io/kion/portal)** at a relative or absolute path, pointed to by `PORTAL_DIR` (default: `../../../../portal`)

### The Makefile

All workflows are in the Makefile. Run `make` (or `make help`) for the full list.

```bash
make deps                       # install ogen + build go-swagger from source
make all                        # regenerate every version from local swagger, build, and test
make build                      # just build (assumes generated/*/oas_*.go exist)
make test                       # unit tests only (integration tests are build-tagged)
make clean                      # remove build artifacts (non-destructive to generated code)
make refresh-spec VERSION=v3_15 # pull swagger from portal/support-3.15.x, regenerate client
make refresh-all                # loop refresh-spec over every SDK version
make scaffold-version VERSION=v3_16  # create client.go and auth.go for a new version
make build-smoketest            # compile the smoketest demo (build tag)
make test-integration           # run integration tests (build tag, needs KION_URL/KION_API_KEY)

make install-oasdiff            # install oasdiff (pinned; one-time, needed for the diff targets)
make diff                       # API changelog between two versions (default v3_15 -> v3_16)
make diff-breaking              # only breaking changes
make diff-summary               # high-level count of changes
```

#### Comparing versions

`make diff` (and `diff-breaking` / `diff-summary`) run [oasdiff](https://github.com/oasdiff/oasdiff)
against two versions' OpenAPI specs to show exactly what changed — useful when a new
Kion release lands and you need to know which operations, schemas, or responses were
added/removed (e.g. to write a CHANGELOG entry or scope downstream work).

```bash
make diff                              # the two newest versions (DIFF_FROM=v3_15 DIFF_TO=v3_16)
make diff DIFF_FROM=v3_14 DIFF_TO=v3_15  # any pair; works on all three diff targets
```

Because `spec/<v>/openapi3.json` is gitignored (derived from portal), the diff targets
require those specs to be present locally first — run `make refresh-spec VERSION=<v>`
(or `make refresh-all`) for each version you want to compare. The targets fail with a
pointer to `refresh-spec` if a spec is missing.

### First-time setup (fresh clone)

The `spec/*/swagger.json` files are not committed — they're pulled from portal on demand. Generated `generated/*/oas_*.go` files ARE committed, so a fresh clone builds immediately without needing portal access:

```bash
git clone https://github.com/kionsoftware/kion-sdk-go.git
cd kion-sdk-go
make build test         # works out of the box
```

To refresh the spec against portal and regenerate:

```bash
make deps               # one-time: install ogen + build go-swagger from source
make refresh-all        # pulls swagger from every portal support branch + regenerates
make test               # verify
```

### Why go-swagger is compiled from source

The `make install-swagger` target clones `go-swagger/go-swagger` at `v0.30.5` and builds the `swagger` binary locally into `bin/swagger`. **It does NOT download the prebuilt `swagger_*_amd64` release binary** — the upstream prebuilt has a known bug (Kion portal issue 8218, upstream [go-swagger#2897](https://github.com/go-swagger/go-swagger/issues/2897)) where it produces swagger JSON files with empty `definitions` and response schemas. The ogen client generated from such a spec has ~250 empty response structs per version and is effectively unusable.

Recompiling go-swagger locally at the same tag produces correct output. Portal's own CI has this same workaround in `devops/portal-ci/jobs/build_swagger.sh`; our Makefile is the local equivalent.

Because go-swagger v0.30.5's transitive dep `golang.org/x/tools@v0.9.3` has a constant expression that Go 1.22+ rejects, the build target sets `GOTOOLCHAIN=go1.21.13` so Go automatically downloads the 1.21 toolchain to compile go-swagger. The resulting binary runs fine under any modern Go.

### Refreshing a single version

```bash
# Requires:
#   - $(PORTAL_DIR) is a clean git checkout of portal
#   - bin/swagger exists (make install-swagger)
make refresh-spec VERSION=v3_15
```

This target:

1. Looks up the portal branch for `v3_15` (`support-3.15.x`)
2. In `$(PORTAL_DIR)`: fetches, checks out the target branch, pulls fast-forward
3. Writes a temporary `info.version` template (required by go-swagger v0.30.5+)
4. Runs `bin/swagger generate spec --input <template> -o spec/v3_15/swagger.json cloudtamer.io/app/webapi` from `$(PORTAL_DIR)/src` (the same way portal's CI does)
5. Runs `fixspec` → `spec/v3_15/openapi3.json`
6. Runs `ogen` → `generated/v3_15/oas_*.go` (preserving hand-written `client.go` and `auth.go`)
7. Verifies `go build ./generated/v3_15/...` passes
8. Restores `$(PORTAL_DIR)` to its original branch via a trap

`make refresh-all` is a loop over `refresh-spec` for every `SDK_VERSION`. Does not touch git state in this repo — it only rewrites files.

### Adding a new Kion version

When portal cuts `support-3.17.x`:

1. Append `v3_17` to `SDK_VERSIONS` in the Makefile.
2. Add a case to the `refresh-spec` portal-branch lookup:
   ```make
   v3_17) portal=support-3.17.x ;;
   ```
3. Populate the new version:
   ```bash
   make refresh-spec VERSION=v3_17
   make scaffold-version VERSION=v3_17
   ```
4. Verify:
   ```bash
   make build test
   ```
5. Commit.

`scaffold-version` generates `generated/v3_17/client.go` and `auth.go` by sed-substituting the package name from `generated/master/` as a template. It's idempotent but refuses to overwrite `master` itself.

Optionally, drop the oldest version once Kion's support window rolls it off: remove `v3_12` from `SDK_VERSIONS`, delete its `spec/v3_12/` and `generated/v3_12/` directories, and remove its case from the `refresh-spec` lookup.

### Drift-prone files (`smoketest` and `integration_test.go`)

`cmd/smoketest/main.go` and `integration_test.go` both access specific response-body fields (like `resp.Data.Value.Items.Value[0].Key`). These field shapes change when portal refactors its swagger response definitions, so both files are behind build tags:

```go
//go:build smoketest
//go:build integration
```

They're excluded from the default `go build ./...` and `go test ./...` so a regeneration that breaks one of them doesn't break the core build. Each targets a specific SDK sub-package (`v3_15`) — bump the import and fix the field access if you want to run them against a different version.

```bash
make build-smoketest            # go build -tags smoketest -o smoketest ./cmd/smoketest
./smoketest                     # KION_URL=... KION_API_KEY=... ./smoketest

make test-integration           # go test -tags integration -v -count=1 ./...
```

### The `fixspec` tool

`cmd/fixspec/main.go` is a small Go binary that converts the raw Swagger 2.0 spec portal produces into an OpenAPI 3.0 spec that ogen can consume cleanly. In order, it:

1. **Sanitizes broken refs** in the raw swagger JSON before kin-openapi parses it — some portal release branches emit dangling `$ref`s to undefined responses (e.g. `support-3.13.x` has `#/responses/CloudProviderType` with no definition). Broken response refs are replaced with inline empty objects, broken parameter refs are dropped, broken definition refs inside parameter schemas are stubbed as empty objects.
2. **Converts Swagger 2.0 → OpenAPI 3.0** via [kin-openapi](https://github.com/getkin/kin-openapi).
3. **Fixes servers**: ensures at least one server URL is set (ogen requires it even though we override at runtime).
4. **Fixes query-string paths**: moves embedded `?key=value` from path keys into proper query parameters. Merges operations that collapse to the same base path.
5. **Fixes circular `$ref`s**: breaks known self-referencing schemas like `FeatureFlagData.features`.
6. **Fills empty schemas**: adds `type: object` to schemas that have properties but no type.
7. **Marks nullable fields**: pattern-based rules for fields the Kion API returns as `null` that the spec declares non-nullable (e.g. `*_id` integers, `deleted_at`, `updated_at`).
8. **Normalizes operation IDs**: strips `apiV1`/`APIBeta` prefixes for clean Go method names.
9. **Adds an API key security scheme** alongside the existing Bearer token scheme.
10. **Adds default response schemas** to responses with no content (prevents ogen errors).
11. **Resolves known schema name conflicts** (e.g. `GCPBillingAccountProjectsResponse`).
12. **Removes `x-go-name` extensions** that ogen doesn't use.

It's invoked as:

```bash
./fixspec -input spec/<version>/swagger.json -output spec/<version>/openapi3.json
```

### Running unit tests

```bash
make test
```

Unit tests live in `kion_test.go` and only exercise the shared helpers in the root package. They don't depend on any generated sub-package, so they always pass regardless of which versions are populated.

### Running integration tests

Integration tests in `integration_test.go` hit a live Kion instance. They're behind the `integration` build tag and require `KION_URL` and `KION_API_KEY` environment variables:

```bash
export KION_URL=https://your-kion.example.com
export KION_API_KEY=app_128_...
make test-integration
```

The file targets `generated/v3_15` specifically — bump the imports if you want to test a different version.

## Troubleshooting

### `ERROR: go-swagger CLI not found`
Run `make install-swagger` (or `make deps`) to build it from source into `bin/swagger`.

### `ERROR: $(PORTAL_DIR) is not a git checkout`
Set `PORTAL_DIR` to the path of your portal clone:
```bash
make refresh-spec VERSION=v3_15 PORTAL_DIR=/path/to/portal
```

### `ERROR: $(PORTAL_DIR) has uncommitted changes`
The refresh-spec target refuses to run if portal has unstaged or staged changes, because it does `git fetch/checkout/pull` against that clone. Commit or stash your portal work first.

### Empty response types in `generated/<version>/`
If `generated/<version>/oas_schemas_gen.go` contains many `type XxxResponse struct{}` (empty structs), your `bin/swagger` binary is the broken upstream prebuilt. Run `make clean && make install-swagger` to rebuild from source.

### ogen INFO logs about "Type is not defined, using any"
Expected — some portal schemas reference types that kin-openapi/ogen can't follow (often circular or dynamic). ogen falls back to `any` (`jx.Raw`) for those. Not an error.

### `go build` fails on `cmd/smoketest` or `integration_test.go` after a refresh
Those files are behind build tags precisely because they're sensitive to per-version schema drift. Default builds skip them. If you're explicitly running `make build-smoketest` or `make test-integration` and hit compile errors, the file needs a small update to match the current `v3_15` (or whichever version it targets) schema.
